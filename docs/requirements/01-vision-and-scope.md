# 愿景、目标与范围

本文档是 forme 的第一份需求文档。它承接 `docs/planning/` 中已经形成的规划基线，但刻意不进入 Rust 技术方案、模块划分、接口设计、数据库 schema 或实施型 PRD。

本文只回答：

- forme 为什么要做。
- forme 要先成为一个什么样的 Agent。
- 面向哪些用户和工作方式。
- 要解决哪些核心问题。
- 当前阶段明确做什么，不做什么。
- 哪些边界必须从第一版开始成立。

## 背景

当前 Agent 工具已经在 coding、办公、自动化、平台协作等方向快速发展，行业实践证明了几个事实：

- Agent 必须有可靠运行时，不只是模型对话。
- 工具执行、权限、沙箱、审批、事件、上下文、MCP、skills、plugins 是现代 Agent 的基础能力。
- 多入口、长任务、session、memory、context compression、subagent、cron/automation 已经成为通用 Agent 的重要组成。
- 用户正在从“问答式 AI”转向“能协作、能执行、能记住、能主动跟进”的 Agent。

但当前这些工具的主动性仍然较弱。它们大多还是用户发起任务，Agent 执行任务。即使有 cron、hooks、插件、上下文记忆，也通常没有把“主动式、长期学习、自我进化、资源协调”作为内核主线。

forme 的机会在这里：

> 构建一个开源的、Rust 编写的、主动式、可进化、可协调、受治理，并能沉淀场景认知地图、支持渐进放权、从失败中学习、持续理解用户也持续理解自身的个人/工作空间 Agent 内核。

它不是要简单复制已有工具，而是站在这些工具的成熟 runtime、控制面、工具生态和安全经验之上，进一步探索真正主动式 Agent 的底座。

## 产品定位

forme 的初始定位是：

> 一个主动式、可进化、可协调、受治理，并能沉淀场景认知地图、支持渐进放权、把失败作为一等证据、能从 seed 逐步成长为用户长期伙伴的个人/工作空间 Agent 内核。

这个定位包含几个关键词。

### 主动式

Agent 不只等待用户输入，也能在授权范围内观察上下文变化，识别机会、风险和待跟进事项，在合适时机提出建议、准备材料、请求确认或执行低风险动作。

主动式不是频繁打扰用户，也不是无限自动化。主动式的核心是：

- 知道什么时候保持沉默。
- 知道什么时候记录和等待。
- 知道什么时候提醒、追问、反证或建议。
- 知道什么时候必须请求用户确认。
- 知道哪些动作不能自动执行。

### 可进化

Agent 不只是保存聊天记忆，也要能从事件、反馈、失败、验证、外部学习和用户行为中形成候选认知，再通过验证、冲突检查、提升和回滚进入更稳定的长期认知。

可进化不等于随意自改。它必须受稳定内核、证据、评估和治理约束。

forme 的长期记忆最终会形成结构化数据库，但这个数据库应通过协作过程逐步生长：交互、任务、工具执行、环境、反馈、失败和反思都应带着时间和证据进入记忆链。外部历史资料可以作为低权重候选证据进入，但不能脱离过程语境一次性塑造稳定用户画像。

Agent 自身也不能停留在初始设定。它需要通过任务结果、工具表现、验证结果、失败证据、用户反馈和主动学习形成 `AgentSelfModel`，理解自己哪些能力可靠、哪些能力不足、哪些协作方式有效、哪些场景需要先学习或先验证。

### 可协调

Agent 不只是拥有工具、skills、MCP、记忆、模型和子代理，还要知道在当前目标下哪些资源值得使用、如何组合、做到什么程度算完成、什么时候应该停、什么时候应该请求用户、什么时候应该先学习或验证。

可协调不等于固定工作流。协调策略可以进化，但资源选择、行动路线、完成标准和策略变更都必须可解释、可评估、可回滚。

### 受治理

Agent 的主动行为、工具执行、长期写入、模型选择、外部系统调用和策略变化都必须有权限、审批、事件记录、可解释性和回滚边界。

受治理意味着：

- 用户控制权优先。
- 高影响动作必须确认。
- 长期认知不能直接写入稳定层。
- 工具和插件不能绕过 runtime。
- 开源项目必须原创实现，不能复制第三方项目。

### 个人/工作空间

forme 面向个人长期使用，也面向一个人的工作空间、项目和协作环境。它需要理解不同项目、上下文、资料、工具、工作节奏和目标，但不把用户复制成另一个自己，而是作为增强型主动助手补强用户。

更长期的关系不是单向服务，而是伙伴式协作。Agent 应围绕用户长期目标成长，放大用户优势、弥补用户短板、扩展用户执行边界，同时通过固定治理内核、权限、证据和用户反馈约束自身进化。

### 场景认知地图

forme 不把长期学习理解为简单 memory 累积。它需要沉淀特定用户、项目、领域和 workflow 的 `CognitiveMap`：哪些判断维度重要、哪些质量标准不能破、哪些工具和来源可靠、哪些盲区反复出现、哪些问题表面是执行问题但本质是目标或框架问题。

### 渐进放权

forme 不追求一开始就全自动。用户对 Agent 的信任应来自具体 scope 下的长期表现、验证结果、失败记录和可撤销授权。权限是硬边界，信任只是放权依据，任何放权都必须有范围、期限、预算、审计和撤销方式。

### 失败证据

forme 把失败视为学习和治理的核心输入。目标误解、上下文遗漏、资源选错、工具失败、自评陷阱、主动打扰、放权过度、验证失败都应被结构化记录，并反馈给认知地图、协调策略、能力评分和信任放权。

## 目标用户

第一阶段不把 forme 限定为某个垂直行业，但需要明确优先用户。

### 核心用户

核心用户是需要长期与 AI 协作的高强度知识工作者，包括：

- 开发者和技术负责人。
- 独立创造者。
- 产品/运营/研究人员。
- 小团队负责人。
- 需要同时管理多个项目、工具、资料和上下文的人。

这些用户通常有以下特征：

- 工作上下文复杂，跨项目、跨工具、跨文档。
- 不满足于一次性问答，希望 Agent 能持续理解和协作。
- 希望 Agent 能主动发现遗漏、风险、机会和待办。
- 愿意给 Agent 授权一部分工具，但需要强控制和审计。
- 需要开源、可本地运行、可扩展、可自定义的底座。

### 非核心但未来可扩展用户

未来可以扩展到：

- 团队协作场景。
- 企业内部知识工作流。
- 多 Agent 项目执行。
- 个人自动化助理。
- 特定行业垂直 Agent。

但这些不是第一阶段的需求中心。

## 要解决的问题

forme 当前要解决的问题不是“再做一个聊天机器人”，而是以下几类问题。

### 1. Agent 过于被动

现有工具大多是用户发起任务后才执行。用户没有说出口的风险、遗漏、重复工作、可学习内容和可提前准备的资料，Agent 很少主动处理。

forme 要解决：

- 如何在授权范围内观察上下文。
- 如何判断是否值得介入。
- 如何控制打扰成本。
- 如何在用户没明确发起任务时仍能准备、学习和跟进。

### 2. Agent 缺少长期认知进化

很多 Agent 有 memory，但 memory 往往是事件记录或摘要，不等于认知进化。

forme 要解决：

- 如何区分事件、经验、反思、知识、技能、原则和策略。
- 如何让新认知先进入候选层。
- 如何验证、提升、降级和回滚长期认知。
- 如何避免新信息覆盖稳定原则或造成认知漂移。
- 如何从普通记忆进一步形成特定场景的认知地图、判断框架、质量模型和盲区模型。
- 如何形成全维度、可演化、有置信度、有时间尺度的 `UserModel`。
- 如何形成全维度、可演化、有置信度、有时间尺度的 `AgentSelfModel`，避免 Agent 永远停留在初始 prompt、初始工具和初始策略上。
- 如何形成 `PartnershipModel`，表达用户与 Agent 如何互补、协作、放权、纠偏和共同成长。
- 如何区分过程证据和历史导入证据，避免一次性全量导入历史资料后静态定义用户。

### 3. 工具很多但缺少统一治理

现代 Agent 需要 shell、file、browser、MCP、API、plugins、skills、hooks、computer use 等大量触点。没有统一治理时，工具会变成安全和复杂度风险。

forme 要解决：

- Agent 怎么知道自己有哪些能力。
- 当前任务应该暴露哪些能力。
- 能力被选中后如何安全执行。
- 工具、插件、MCP、hooks 如何不绕过权限和审计。
- 工具使用结果如何反馈到能力评估和学习系统。

### 4. Agent 缺少资源协调和行动路线能力

现代 Agent 很容易拥有大量资源：长上下文、记忆、工具、skills、MCP、插件、子代理、模型路由和外部资料。但资源多不等于能力强。真正影响结果的是 Agent 能否根据目标选择最合适的资源组合，并形成可验证、可恢复、可回滚的行动路线。

forme 要解决：

- 如何把用户目标或主动机会转成 GoalFrame。
- 如何判断当前需要哪些 context、memory、tool、skill、MCP、model、subagent 或外部资料。
- 如何形成 ResourcePlan、DoneContract 和 ExecutionRoute。
- 如何避免 over-tooling、under-tooling、自评陷阱和长任务失控。
- 如何从 DecisionTrace、OutcomeEvaluation 和用户反馈中改进协调策略。
- 如何让协调策略读取认知地图、信任状态和失败证据，而不是只依赖模型临时判断。

### 5. Agent 缺少渐进信任和失败学习机制

一个主动式、可协调、可进化的 Agent，如果用户不敢放权，就只能停留在建议层；如果失败不能被结构化吸收，就无法真正进化。

forme 要解决：

- 如何区分 permission、approval、trust、delegation。
- 如何设计从只读、建议、准备、审批执行到预授权执行的放权曲线。
- 如何记录和解释失败，而不是用最终回答掩盖失败。
- 如何让失败影响后续信任、能力评分、认知地图和协调策略。
- 如何避免一次成功导致过度放权，一次失败导致非理性全盘否定。

### 6. 多入口和长任务缺少统一边界

主动式 Agent 不能只存在于一次 CLI 对话。它需要支持未来的桌面、Web、API、消息入口、定时任务和后台任务。

forme 要解决：

- 不同入口如何进入同一个 runtime。
- session、run、turn、approval、event 如何统一。
- 后台任务如何可观察、可取消、可恢复。
- 不同入口的数据和权限如何隔离。

### 7. 开源原创需要边界

forme 计划开源，不能复制第三方的源码、文档、结构和产品表达。

forme 要解决：

- 如何从问题出发形成抽象设计。
- 如何建立原创性与合规边界检查机制。
- 如何避免第三方源码、来源不明材料或文档表达进入主工程。
- 如何保持原创 Rust 实现和原创文档体系。

## 产品目标

### 长期愿景

forme 的长期愿景是成为一个开源的主动式 Agent 内核：

- 能长期理解用户、项目、工具和工作空间。
- 能主动发现机会、风险、待办和学习议题。
- 能在授权范围内准备、建议、跟进和执行。
- 能从经验中学习，并通过受控机制进化。
- 能协调模型、工具、记忆、skills、MCP、subagent、用户注意力和外部资料，形成高质量行动路线。
- 能沉淀特定用户、项目和工作流的认知地图。
- 能通过可解释、可撤销、可审计的机制逐步获得用户放权。
- 能把失败转化为后续认知、协调、能力和信任校准的证据。
- 能通过 AgentSelfModel、能力链和伙伴关系模型持续理解自身，逐步从 seed Agent 成长为更可靠的主动式智能伙伴。
- 能接入多种工具、模型、MCP、插件和入口。
- 能让用户始终理解、控制和审计它的行为。

### 第一阶段目标

第一阶段不是实现完整自治，而是把底座边界做对。

第一阶段目标：

- 固定主动式 Agent 的产品定位和边界。
- 明确 M0/M1/M2/M3 的需求方向。
- 建立可演进的 AgentHarness 需求。
- 建立主动式、认知进化和资源协调的最小需求闭环。
- 明确能力基质和执行触点的需求范围。
- 明确开源原创实现约束。
- 为后续能力需求、技术方案和实施型 PRD 提供稳定输入。

## 范围

### 当前范围内

当前需求范围包括：

- Agent 的定位、用户、使用边界和产品目标。
- 主动式能力的定义和等级。
- 长期学习和认知进化的需求边界。
- 协调内核、资源选择、完成合同和决策轨迹的需求边界。
- 场景认知地图、信任放权和失败证据的需求边界。
- 工具、MCP、skills、plugins、hooks 的能力需求边界。
- shell、file、browser、computer use、API connector 等执行触点的范围定义。
- Gateway、多入口、session、background job 的范围定义。
- 模型配置、provider、routing、profile、secrets、ConfigDoctor 的范围定义。
- 权限、审批、审计、事件、回滚的产品边界。
- 原创性与合规边界检查要求。

### 当前范围外

当前不做：

- Rust workspace 初始化。
- crate 划分。
- API/interface/schema 设计。
- 数据库表结构设计。
- UI 设计。
- 完整 PRD。
- 具体模型供应商选择。
- 具体插件市场设计。
- 完整 autonomous agent 承诺。
- 复制或移植第三方项目的模块。

## 主动等级范围

forme 的主动性必须分级，而不是一个开关。

| 等级 | 含义 | 第一阶段态度 |
|---|---|---|
| L0 Observe | 授权范围内观察和记录，不打扰。 | M0 进入最小主动闭环。 |
| L1 Suggest | 延迟摘要、轻提醒、建议。 | M0 形成受治理 proposal，M1 增强体验。 |
| L2 Prepare | 准备材料、草稿、分析、计划。 | M0 保留 proposal 与 approval 边界，M1/M2 增强。 |
| L3 Act With Approval | 请求确认后执行写操作或外部动作。 | M0 固定治理边界，后续逐步开放。 |
| L4 Act Autonomously | 预授权低风险自动行动。 | 研究目标，不作为 M0/M1 承诺。 |
| L5 High Impact | 高影响外部动作或不可回滚动作。 | 必须审批，不做自动自治。 |

第一阶段应重点保证 L0-L2 的最小闭环和治理正确，L3-L5 固定治理边界但不默认开放高自治。

## 成功标准

当前需求阶段的成功标准不是“能跑起来”，而是：

- 能清楚说明 forme 与通用任务型 Agent 工具的区别。
- 能清楚说明主动式不是普通通知、cron 或 memory。
- 能清楚说明哪些能力属于 M0，哪些只是未来方向。
- 能清楚说明用户控制、权限、审批和开源原创边界。
- 能让后续 `02-capability-requirements.md` 按能力域自然展开。
- 能让技术方案阶段避免重新争论产品定位。

## 非目标

forme 不追求：

- 第一版成为无需用户参与的全自动 Agent。
- 第一版覆盖所有办公、浏览器、桌面和消息平台。
- 第一版覆盖完整控制面、全部工具生态或完整 coding 产品体验。
- 用 prompt 假装治理。
- 用 memory 假装认知进化。
- 用流水账 memory 假装场景认知地图。
- 用 cron 假装主动式。
- 用 tool routing 假装资源协调。
- 用 trusted mode 假装渐进放权。
- 用错误日志假装失败学习。
- 用一次性全量数据导入假装理解用户。
- 用初始 prompt、角色卡或静态 Agent profile 假装 Agent 成长。
- 用“伙伴关系”绕过用户控制、权限、审批或高影响决策边界。
- 以任何理由复制第三方实现。

## 关键约束

### 用户控制

用户必须能理解、暂停、拒绝、撤销或降低 Agent 的主动性。

### 授权优先

Agent 只能观察和行动于授权范围内。授权范围必须可表达、可检查、可审计。

### 候选先于稳定

长期认知、策略、技能、原则不能由单次反思直接进入稳定层。

### 放权可撤销

放权必须有 scope、期限、预算、动作类型和撤销机制。信任不能突破权限，权限不能只存在于 prompt 中。

### 失败可学习

失败必须进入结构化证据流。验证失败、审批拒绝、用户撤销、主动打扰和任务偏航都不能被最终输出掩盖。

### 执行受治理

所有真实行动必须经过 policy、approval、event 和 backend 约束。

### 开源原创

所有实现和文档必须以 forme 自己的设计为准。

## 当前结论

forme 当前需求方向可以收敛为一句话：

> 做一个开源、Rust、主动式、可进化、可协调、受治理，并具备场景认知地图、渐进放权和失败证据边界的个人/工作空间 Agent 内核；第一阶段先把主动式底座、认知进化边界、协调内核、能力基质、执行触点、模型/网关配置和开源原创边界定义清楚，再进入能力需求、技术方案和实施型 PRD。
