# 产品收尾的证据分界与下一执行方案（2026-11-06）

本记录用于把整体目标收口到可执行结果，不新增内核或产品功能，不授权停服、迁移、删除、重新安装或新的系统虚拟化设置。当前生产收集器的源码验证与原机历史审查是两件事；后者缺少的过去事实不能靠更多当前测试生成。

## 1. 原机实际状态与无法从代码补出的材料

原 installation 为 `installation:969387966500ba7c649fcc449c073cd5d27042b2b2989f2eda3c7a8d5f376258`；原 operation 为 `maintenance:acceptance-upgrade-after-path-20261102-db96ec2`。2026-11-06 本轮只读复核：Host/Web Running，Brain/updater Stopped，18765 页面入口 HTTP 200。原程序、账号、脑、模型配置、keys、journal、旧操作和失败回执保持；当前源码没有部署到原安装。

[八项材料状态](installed-legacy-recovery-evidence-status-20261106.md)仍有三个独立历史来源缺口：故障前数据档案的可接纳 origin；原 exe 到已审计源码/构建的可信绑定；worker/lease 的历史连续性。现有历史输出可以证明部分原观察，却没有满足已批准来源协议的完整资格。不能现场创建 origin、倒填时间、补签，不能把当前静止解释成历史从未执行。

继续原地恢复必须先取得这些来源，再形成完整独立审查，准备准确管理修复 plan、签名闭合包、原件保护备份和原机窗口。只有 Verified 才能用新 owner 决定将旧升级明确结束为 Aborted；不能重发旧 Upgrade、清空 journal 或自动放开维护互斥。没有来源就维持 Unverifiable，不重复停服采样或整仓回归。

## 2. Owner 已选择的路线：先处理旧记录，再在本机测试

owner 最新要求“把之前的那个未完成升级先处理掉，之后直接在本机来进行测试”。这一要求取代此前 VM 选择；当前不用提供虚拟机位置，也不创建新环境。

优先尝试已批准的独立历史审查与原操作显式裁决，但现存材料尚不满足 Verified，不能将旧记录安全标为 Aborted。精确旧源码重建也没有复现旧二进制摘要。若原来源确实从未产生，应准备“完整保全旧测试安装和未决历史，再在同机重新部署”的具体方案供审查；明确新旧实例身份/账号/数据/配置关系及准确目录、服务、注册项、候选与恢复操作。这不等于旧升级安全取消，也不授权清空 journal、丢弃数据或顺带复用原密钥。

原机部署前提解决后，按既有 PRD24–26 和 IP01–IP24 完成一个连续验收：

1. 从当前提交重建 release，核对闭合包、独立签名、六程序与静态 UI，明确原地升级或已审查保全重建的前提；独立核验四个 SCM 注册、账户、恢复策略、ACL、实际程序和端口。
2. 经网页认领、建立独立测试 owner、登录、配置真实 provider；模型配置后验证自动 Brain 启动、实际加载 ack 与准入，不手动拼装另一套 runtime。口令/密钥不进报告。
3. 浏览器走正式 Web→Gateway→ProductionRuntime；验证真实对话、工具审批与隔离副作用、项目/收件箱/认知/设置、跨刷新与重启的记忆。验事件、状态和实际结果，不以模型自述或 HTTP 200 代替。
4. 在明确的本机验收窗口执行 Host/Web/Brain 分别重启、掉线、桌面 helper 与非交互 worker、配置事务、LAN/TLS 和数据管理的正反场景；整机重启、注销、卸载及影响其他应用的动作另行协调准确范围。
5. 以从一开始就记录了恢复基线的新 installation 执行签名升级/兼容回滚、崩溃与原号核实，保留每次副作用和 Unknown，不制造旧安装的历史来源。再按单独记录的准确范围验卸载保留数据。
6. 逐项填写 IP 和平台矩阵，刷新适用核心/闭合/发布门及源代码工件回执。只有需要的真实场景均取得证据后，才标记相应目标完成；模型或桌面环境不足的项继续明确列出。

原 owner/store、keys 与旧 journal 全部受原协议保护。原脑迁移另走已有数据接管/恢复准入，不顺带复制或覆盖数据库/keys。旧安装处置和当前版本验收分别登记；本机开发签名仍不等同正式发行。

## 3. 判定何时停止继续开发

生产收集器是本轮历史恢复路径的明确实现缺口；完成其真实装配、材料重查和正反验证后，不继续为了凑齐旧历史而增加协议。下一阶段应让当前签名版本在真实、可用且已确定的 Windows 验收环境运行 IP；各项实现义务同时按 PRD 和实际消费者核对，不继续迭代无法补出过去事实的来源判定概念。

本轮完工不表示 PRD24–26 的全部代码均已完成。当前 `ProductConfigAvailability::managed` 仍将 MCP、plugins、packages、channels 标为 `unavailable / managed_consumer_missing`；`ProductCapabilitySettings` 的受管配置消费者只有 skills。已有 core M5 能力不等于安装版已接入这些产品消费者。它们属于原设计中的后续接入义务，应继续保持真实状态，不能靠虚拟机验收消除，也不能把“不可用显示正确”解释成完整能力已经实现。后续接入沿既有 M5/ChannelAdapter、Host 配置事务、隔离执行与 Web 身份边界推进；涉及冻结对象或 trait 的变化，先形成准确契约变更再实施。

本机开发签名只用于已经选择的受控验收，不等同正式发行证书。Linux/macOS 仍按 owner 已选的有限策略与 `release_ready=false` 边界；没有原生环境就不把跨编译或测试通过写成平台 PASS。正式发布、原机恢复及产品场景各自保留完成条件。
